# Decisions log

Append dated entries when deviating from SPEC.md or making a notable technical choice.

- 2026-09-24: Project named "Baton" (handoffs between people and agents). Stack per SPEC.md section 2.
- 2026-09-24: Toolchain pinned to what typescript-eslint supports: TypeScript 6.0 (TS 7 is out, but typescript-eslint 8 requires TS < 6.1). Also on the latest majors: Vite 8, Vitest 5, ESLint 10, React Router 8 (SPEC says 7; its route-object API is unchanged), Drizzle ORM 0.45 (1.0 is still beta), @hono/node-server 2.
- 2026-09-24: Better Auth tables were generated with the Better Auth CLI (`auth generate`, username + emailOTP plugins). `user.theme` is an enum column, NOT NULL, default `'system'`. The auth config must declare it as `{ type: ['system','light','dark'], required: true, defaultValue: 'system', input: false }` and set `advanced.database.generateId` to `newId` (ULIDs).
- 2026-09-24: Author, actor, creator, uploader, resolver, claimer and deleter FKs are nullable with `ON DELETE SET NULL`, so content survives account deletion and shows a "deleted user". `team.owner_id` is `RESTRICT`, because account deletion is blocked while the user owns a team.
- 2026-09-24: The `activity` table has no foreign keys (only indexes), so the append-only audit log outlives purged entities. The per-user security log lives in `activity` rows with `team_id` NULL and `entity_type` `user` or `api_key`.
- 2026-09-24: `attachment.team_id` is nullable, only for `user_avatar` uploads, which belong to no team.
- 2026-09-24: Extra constraints beyond SPEC §4: `status` is unique per (project, name), with a partial unique index allowing one default status per project; `role` allows one `is_everyone` role per team (partial unique); `task_dependency` has a CHECK against self-blocking. Team slugs and project keys are unique only among non-deleted rows (partial unique indexes), so restoring an item whose slug or key was reused is a `conflict`.
- 2026-09-24: `search_index` (FTS5) makes `entity_type` UNINDEXED too (SPEC lists it as indexed), so the word "task" in a query doesn't match every task. Filter types with `entity_type IN (…)`. It uses the `porter unicode61 remove_diacritics 2` tokenizer with `prefix='2 3'` for as-you-type search.
- 2026-09-24: Live events carry `teamId: string | null` plus an optional `userId` (the recipient of personal events), because `me.updated` has no team. For `activity.created`, `parentType`/`parentId` name the entity the activity row is about.
- 2026-09-24: Wire timestamps are ISO 8601 strings. Attachment deletes and other deletes return `{ ok: true }`. `GET /api/subscriptions?entityType&entityId` was added to the core contract so pages can show the subscribe toggle.
- 2026-09-24: `BASE_URL` defaults to `http://localhost:5173` (the Vite dev server) in development and to `http://localhost:$PORT` otherwise. Production requires it to be set. `.env` in the working directory is loaded when present, and real environment variables take precedence.
- 2026-09-24: The server resolves the SPA build from the working directory (`dist/web`), like Hono's `serveStatic`. The server bundle keeps all npm packages external (production runs from a checkout with `node_modules`), and the build copies the SQL migrations to `dist/server/migrations`. `npm run db:migrate` runs `server/db/migrate-cli.ts` through tsx.
- 2026-09-24: MCP tools are declared with `defineTool` (`server/mcp/tools/define.ts`) and collected into one list per module. `registerTools` registers them on each per-request `McpServer`.
- 2026-09-24: The foundation implements the backup job (`server/jobs/backups.ts`: `VACUUM INTO`, keep 14, mirror uploads). Claim and purge jobs remain for the tasks and core modules.
- 2026-09-24: Role `position` ranks higher-is-higher (Discord style). `@everyone` is always 0, and the seeded Admin role is 1. Status `position` is an integer column order, ascending.
- 2026-09-24: Removed `next-themes`, which shadcn's sonner component pulls in. The Toaster uses `web/lib/theme.ts`. shadcn `use-mobile` and the sidebar skeleton were adjusted to satisfy the React Compiler lint rules (no setState in effects, no `Math.random` during render).
- 2026-09-24: `npm audit` reports 4 moderate advisories in drizzle-kit's dev-only `@esbuild-kit` dependency (esbuild dev-server CORS). They don't reach production, so they are accepted until drizzle-kit drops the dependency.
- 2026-09-24: `dev:server` runs `node --watch --import tsx` instead of `tsx watch`. Under `concurrently` on Windows, the `tsx watch` child hung before it could listen, probably because of how its IPC channel is inherited. Logs are always JSON, and `dev:server` pipes them through the `pino-pretty` CLI. An in-process pino-pretty transport was dropped, so production never loads a dev dependency.
- 2026-09-24 (core): Live events can be queued inside a transaction with `queueLiveEvent(tx, …)` (re-exported as `emitAfterCommit` from `server/services/events.ts`); `db.write` delivers them after commit and drops them on rollback. `recordActivity` uses it to emit `activity.created` for every row, so feature services get audit-log live updates for free. Account-level rows (team `null`) are delivered only to their user (`userId`), like personal events.
- 2026-09-24 (core): The MCP endpoint is stateless, so only `POST /mcp` is served; `GET` and `DELETE /mcp` answer 405 with `Allow: POST` (what the MCP spec prescribes for servers without sessions or server-initiated streams), instead of opening a stream that could never carry anything.
- 2026-09-24 (core): The 10/min/IP auth limit counts `POST /api/auth/*` only; session reads (`get-session`) and OAuth redirects are not throttled, or the web app would lock itself out. Better Auth's own per-path limits stay on (3 sign-in/sign-up attempts per 10 s, one code email per 60 s as the resend cooldown), backed by the app's token buckets (`deps.rateLimiter`) instead of Better Auth's process-global memory store. The client IP reaches Better Auth through an internal `x-baton-client-ip` header set from `CF-Connecting-IP` (`TRUST_PROXY=cloudflare`) or the socket address; a client-supplied value is always stripped.
- 2026-09-24 (core): OAuth sign-ups are stored with `emailVerified = true` (SPEC §1.1). Google and GitHub are "trusted providers" for account linking as specified, but a link whose provider email is _not_ verified is only accepted when the account owner started it while signed in (`user.validateUserInfo`), so an unverified GitHub email can't be used to take over the Baton account with that address.
- 2026-09-24 (core): Better Auth endpoints outside the SPEC are disabled: `sign-in/email-otp` (a code alone never signs anyone in or up), email change, and `delete-user` (account deletion belongs to the account module, which must block it while the user owns a team). One-time codes are stored hashed. Username input is accepted in any case and stored lowercase; sign-up without a username is refused.
- 2026-09-24 (core): Security-log actions: `user.signed_up`, `user.signed_in` (meta: method, ip, userAgent), `user.password_changed`, `user.password_reset`, `user.password_set`, `user.account_linked`, `user.account_unlinked` (meta: provider), `api_key.created`, `api_key.revoked`. They are served by the added `GET /api/me/security-log`.
- 2026-09-24 (core): Notification read state and reply subscriptions are personal preferences, not team mutations, so they write no audit rows. System cleanup writes `<type>.purged` rows for items purged from Trash; unclaimed pending uploads are purged without audit rows (they were never visible to anyone but the uploader).
- 2026-09-24 (core): Soft-deleted items keep their search-index rows (restores need no reindex); search filters deleted items, replies of deleted items and deleted projects/teams at query time, and the trash purge removes the rows.
- 2026-09-24 (core): Pending uploads are visible only to their uploader; `user_avatar` attachments (no team) are readable by any signed-in user so avatars can be shown across teams. Uploading directly to a parent needs edit rights on it (tasks also accept `UPDATE_TASKS`, projects need `MANAGE_PROJECTS`). A user can hold at most 50 active API keys, and keys can only be managed from a web session.
- 2026-09-24 (core): Contract additions (additive): `GET /api/me/security-log`, `GET /api/attachments?parentType&parentId`, and the trash schemas (`trashItemSchema`, `trashListResponseSchema`, `trashItemRefSchema`) that the admin module's routes will serve from `listTrash`/`restoreItem`.
- 2026-09-24 (core): `E2E_MAILBOX=true` (test-only env var) makes the mailer also write every email as JSON into `DATA_DIR/mailbox/` (including `kind` and `code`), so end-to-end tests can complete verification and reset flows.
- 2026-09-24 (core-web): The theme has no React provider. It stays a small external store (`web/lib/theme.ts`, `useSyncExternalStore`) applied before first paint by `public/theme-init.js`. Saving to the profile is an extension point: the account module registers `useThemePersister(fn)` from a shell extension, and `useSyncProfileTheme` applies profile changes made on other devices (a device with no saved choice adopts the profile's theme).
- 2026-09-24 (core-web): The session comes from Better Auth's `GET /api/auth/get-session` (200 with `null` when signed out, so logged-out visits log no 401s). The profile comes from `GET /api/me`. Guards: `RequireAuth` (session), `RequireOnboarded` (verified email + username, else `/verify-email` or `/onboarding/username`), `RedirectIfAuthed` (sign-in pages → `?next`). `?next` accepts same-origin paths only.
- 2026-09-24 (core-web): The web client sends verification codes itself (after sign-up, and when sign-in fails with `EMAIL_NOT_VERIFIED`) via `emailOtp.sendVerificationOtp`, and resets passwords with `emailOtp.requestPasswordReset` + `emailOtp.resetPassword`. The server should therefore not auto-send on sign-up (`sendVerificationOnSignUp: false`) and should set `emailVerification.autoSignInAfterVerification: true`. Without auto sign-in, the verify page sends the user to the login page instead. OAuth users set their username with Better Auth's `updateUser({ username })`. The login field accepts an email or a username (`signIn.username`).
- 2026-09-24 (core-web): Shell extension points: `web/components/layout/shellExtensions.ts` (a registration list of lazy components mounted once inside the signed-in shell), `web/lib/shellActions.ts` (typed actions such as `team.create`; controls stay hidden until a module registers a handler), and the palette registry (`usePaletteCommands`, `registerSearchProvider`) in `web/components/palette/registry.ts`. The sidebar's "New team" button therefore appears only once the teams module registers `team.create`.
- 2026-09-24 (core-web): Editor markdown is normalized on output (`web/components/editor/markdown.ts`). Autolinks (`[url](url)`, `[email](mailto:email)`) are written bare, and surrounding blank lines are trimmed. Tables are written in `@tiptap/markdown`'s padded GFM form, which parses back to the same table. Mentions are `@username`, `@&role-slug` and `@everyone` (`web/lib/mentions.ts`). The mention suggestion lists users and roles together, and typing `@&` filters to roles.
- 2026-09-24 (core-web): The development component gallery is `/__dev/components`. It is added only when `import.meta.env.DEV` is true, so production builds drop it. The visual review suite (`npx playwright test -c e2e/visual/visual.config.ts`) runs against the Vite dev server with the API mocked in the browser, and writes screenshots to `test-results/visual/`. `playwright.config.ts` reads `E2E_PORT` (default 3000), so parallel checkouts can run e2e side by side.
- 2026-09-25 (integration): `.npmrc` sets `ignore-scripts=true`. npm 11 runs an implicit `node-gyp rebuild` for better-sqlite3 13 because it ships a `binding.gyp` (its `gypfile: false` is ignored), which fails without a C++ toolchain (no Visual Studio on the Windows dev machine, no build-essential on the no-sudo Ubuntu host). better-sqlite3 13 loads its bundled prebuild (`prebuilds/<platform>.node`) and needs no build step. The only other install scripts in the lockfile are esbuild's `postinstall` (it only verifies/optimizes the platform binary from the `@esbuild/*` optional package, which the JS API and CLI shim find without it) and fsevents (macOS only). Consequence: `npm ci`/`npm install` never run dependency lifecycle scripts; a future dependency that truly needs one must be built explicitly (`npm rebuild <pkg> --ignore-scripts=false`). Playwright browsers are installed explicitly anyway (`npx playwright install chromium`).
- 2026-09-25 (integration): The server emails the first verification code as part of `sign-up/email` (`emailVerification.sendOnSignUp`, as docs/API.md states); the web sign-up page no longer requests a second code (which superseded the first and sent two emails) and only starts the resend cooldown. The core-web entry above that asked for `sendVerificationOnSignUp: false` is superseded. The login page still requests a code when signing in with an unverified email (`sendOnSignIn` is off).
- 2026-09-25 (integration): `POST /api/auth/is-username-available` is not counted by the 10/min/IP auth limit: it is a read that the sign-up and onboarding forms call as the user types, and it would otherwise use up the budget for signing up. Better Auth's own limit (100/min/IP) still applies to it.
- 2026-09-25 (integration): The Playwright suite (`npm run test:e2e`) runs the production build with `TRUST_PROXY=cloudflare`, and every test sends its own `CF-Connecting-IP`, so the per-IP auth limits apply per test rather than throttling the whole suite (all tests share one socket address). Emails are read from `DATA_DIR/mailbox/` (`E2E_MAILBOX=true`); SMTP and OAuth variables are forced empty so a developer's `.env` can't leak into the run. DATA_DIR is `<tmp>/baton-e2e-<port>` (`e2e/support/env.ts`), wiped on every run.
- 2026-09-25 (review fixes): `markdownToPlainText`, `excerpt` and `stripCode` (server/lib/markdown.ts) run in linear time on 100 KB bodies: no scanning class may run past the next opener of its own construct, emphasis delimiter runs are dropped by looking at their neighbours instead of being paired (`user_id`, `a*b` and `2 * 3` stay as text), code spans are paired with a one-pass table, and `excerpt` converts at most 8x its length. Services compute search text and excerpts before `db.write` (`SearchDocument.text` is plain text now), so no text processing runs while the write lock is held.
- 2026-09-25 (review fixes): `POST /mcp` refuses JSON-RPC batch arrays (400, -32600; batching was removed from MCP in 2025-06-18), so the 300/min/key limit counts messages. The body limit is `ceil(MAX_UPLOAD_MB x 4/3) + 64 KiB` (a base64 upload of the maximum size), replacing the SDK's 4 MiB default; `upload_attachment` also takes a token from the per-user uploads bucket (30/min), like `POST /api/attachments`. MCP writes are not charged to the REST writes bucket: SPEC §5 gives MCP its own per-key limit. `whoami` reports `limits.maxUploadMb`.
- 2026-09-25 (review fixes): `GET /api/activity` / MCP `get_activity` without `VIEW_AUDIT_LOG` only serve per-item history (issue, task, reply, attachment); the history of the team, members, roles, invites, projects, statuses and labels is part of the audit log and answers 403. Items in Trash (or inside a trashed item or project), and their attachments, follow the Trash visibility rules (author or `MANAGE_TRASH`, else 404), and a pending upload's history is visible to its uploader only. The same Trash rule now applies to reading and downloading attachments (`readableAttachment`).
- 2026-09-25 (review fixes): Verification codes are only sent to unverified addresses: `send-verification-otp` for a verified address (or with a type other than `email-verification`) answers `{ success: true }` without sending, and `verify-email` for a verified address answers like an unknown code. `autoSignInAfterVerification` stays on, so a verification code can only ever sign in the owner of a not-yet-verified account.
- 2026-09-25 (review fixes): Better Auth profile input is checked in `hooks.before` (`sign-up/email`, `update-user`): `name` is trimmed and 1-64 characters, `displayUsername` must equal the username case-insensitively (and follows username changes), and `image` can only be cleared or set to the user's own `user_avatar` upload (`/api/attachments/<id>/<name>`, relative or absolute).
- 2026-09-25 (review fixes): Attachment downloads send `Content-Type: application/octet-stream` for everything that is not an inline raster image (the real type stays in the metadata) and a per-response `Content-Security-Policy: default-src 'none'; sandbox`.
- 2026-09-25 (review fixes): An open `GET /api/events` stream re-checks its API key or web session (by session id) before every event and heartbeat, and ends once the key is revoked or expired or the session is gone (sign-out, revocation, password reset).
- 2026-09-25 (review fixes): The bundled server (`npm start`) defaults `NODE_ENV` to `production` (esbuild defines `BATON_BUNDLE_NODE_ENV`), and `BETTER_AUTH_SECRET` is required in any mode when `BASE_URL` is not a loopback address; the server warns at startup whenever the development secret is in use.
- 2026-09-25 (review fixes): Deviation from SPEC §1.11 "same transaction": the security-log rows written from Better Auth hooks (`user.signed_up`, `signed_in`, `password_changed`, `password_reset`, `password_set`, `account_linked`, `account_unlinked`) are written right after Better Auth commits its own change, in a separate transaction. Better Auth's drizzle adapter is asynchronous and our `db.write` is a synchronous `BEGIN IMMEDIATE`, so the two cannot share one. A failed log write is logged at error level and does not fail the request.
- 2026-09-25 (review fixes, web): Routes have two error elements (`RouteError`): one inside the app shell (the sidebar stays usable) and one around everything else. A failed page chunk (typically an open tab after a deploy) reloads the page once, guarded by `sessionStorage` for 30 s, then shows "Baton was updated" with Reload and Back to dashboard. There is no `vite:preloadError` listener: letting the error reach the route means the reload happens at the page the user was going to.
- 2026-09-25 (review fixes, web): `safeNext` resolves `?next` with the URL parser against a placeholder origin and rejects control characters and whitespace, so nothing a browser would read as another origin reaches the router.
- 2026-09-25 (review fixes, web): Palette and picker items use their id as the cmdk `value` and their display text as the first keyword; `commandFilter` (web/lib/commandFilter.ts) scores only the display text and hides matches below 0.1, so ids never match and a weak fuzzy hit cannot outrank the item typed. The palette turns off cmdk's vim bindings so Ctrl+K toggles it.
- 2026-09-25 (review fixes, web): The editor's markdown goes through `BatonMarkdownManager` (web/components/editor/markdownManager.ts), a subclass of `@tiptap/markdown`'s manager installed by `BatonMarkdown`. It escapes text only where the character would change the markdown in context (no HTML entities; `user_id`, `2 * 3`, `array[0]`, `R&D`, `C:\Users` stay as typed), decodes non-ASCII entities when parsing, lets marks cover mentions (`**@alice**`, `[@alice](url)` round-trip) and skips empty paragraphs instead of writing `&nbsp;`. Two of its hooks replace private methods of the library (`encodeTextForMarkdown`, `applyMarkToContent`); the constructor throws if they disappear and markdown.test.ts covers the behaviour, so an upgrade of `@tiptap/markdown` must re-run those tests. Table cells escape every `|` (`BatonTable`), including inside code spans.
- 2026-09-25 (review fixes, web): Markdown the editor cannot edit is kept verbatim as atomic source chips/blocks (`rawInline`, `rawBlock`): inline HTML tags and comments, HTML blocks, and GFM footnote references and definitions. `<br>` stays a hard break (table cells write line breaks as `<br>`). MarkdownView still sanitizes HTML away on display; its footnote links work because the sanitizer no longer adds a second `user-content-` prefix (`clobberPrefix: ''`; raw HTML never renders, so remark-rehype's prefixed footnote ids are the only ids).
- 2026-09-25 (review fixes, web): Mention chips in MarkdownView resolve through an exact lookup of the names in the body (`GET /api/teams/:teamId/mentionables?usernames&roles`, additive to the core contract) instead of the first 20 autocomplete candidates. Removing a file from an unsent reply draft (`AttachmentList removeMode="draft"`) is immediate and says "Remove", not "moves to Trash".
- 2026-09-25 (account): Avatars are uploaded with `POST /api/me/avatar` instead of `POST /api/attachments` (which refuses `user_avatar` and needs a team). They are `attachment` rows with `parent_type = 'user_avatar'`, `parent_id` = the user and `team_id` NULL: PNG, JPEG, GIF or WebP recognised by their bytes, at most 5 MB (never more than `MAX_UPLOAD_MB`). Replacing or removing an avatar hard-deletes the old row and file: avatars belong to no team, so they never go to Trash.
- 2026-09-25 (account): Changing the password and setting one (OAuth-only accounts) are account-service endpoints (`POST /api/me/password`, `POST /api/me/password/set`), not Better Auth's `/change-password` and server-only `setPassword`. They hash and verify with Better Auth's own functions (`auth.$context.password`) and write the `credential` account row directly, so the `user.password_changed` / `user.password_set` row shares the transaction, and "sign out other sessions" deletes the other sessions but keeps the current one (Better Auth deletes all of them and issues a new session, which its hooks would log as a sign-in).
- 2026-09-25 (account): Sessions are listed and revoked by the account service from the `session` table: Better Auth's `list-sessions` and `unlink-account` require a "fresh" session (created less than a day ago) and fail otherwise. `lastActiveAt` is the session's `updated_at`, which Better Auth refreshes at most once a day, so it is accurate to a day. Disconnecting Google or GitHub is `DELETE /api/me/connections/:provider` for the same reason; it also logs the provider (Better Auth's endpoint only receives the account row id, so core's `user.account_unlinked` hook row would say `provider: null`). Connecting still goes through Better Auth's `link-social` redirect flow.
- 2026-09-25 (account): Password, session, sign-in-method and account-deletion endpoints need a web session (API keys get 403), per SPEC §1.14. Account deletion is not an MCP tool: it requires the account password, which must never be handed to an agent. Profile, theme and avatar changes work over MCP (`update_profile`, `set_avatar`, `remove_avatar`) and REST with keys, and the security log is readable over MCP (`get_security_log`).
- 2026-09-25 (account): Theme changes are audited like other profile changes (`user.profile_updated` with a `theme` change). On the first load of a new sign-in the web app adopts the theme saved in the profile (the session id is remembered in localStorage `baton-theme-session`); after that the local choice wins and is saved to the profile.
- 2026-09-25 (account): Account deletion is blocked while the user owns any team, Trash included (`team.owner_id` is `RESTRICT` until the purge). Deleting removes the user row (cascading to sessions, accounts, API keys, memberships, member roles, task assignments, subscriptions and notifications) plus the user's avatar and pending uploads (rows and files); authored content keeps a null author ("Deleted user"). Each team the user was in records `member.account_deleted` (meta: username, name) and gets a `member.left` live event. Task claims held by the user are not released explicitly: they expire like any other lease.
- 2026-09-25 (account): Labels of linked accounts on the connections page: Google shows the `email` claim of the stored ID token; GitHub shows the login from `https://api.github.com/user`, read with the stored access token (3 s timeout, no label on failure).
- 2026-09-25 (account): `shared/schemas/teams.ts` was created in the account branch with only the deleted-teams contract (`deletedTeamSchema`, `deletedTeamsResponseSchema`) so the account settings page can consume it; the teams module owns the file, and its version wins on merge.
