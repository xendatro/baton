# Decisions log

Append dated entries when deviating from SPEC.md or making a notable technical choice.

- 2026-09-24: Project named "Baton" (handoffs between people and agents). Stack per SPEC.md section 2.
- 2026-09-24: Toolchain pinned to what typescript-eslint supports: TypeScript 6.0 (TS 7 is out, but typescript-eslint 8 requires TS < 6.1). Also on the latest majors: Vite 8, Vitest 5, ESLint 10, React Router 8 (SPEC says 7; its route-object API is unchanged), Drizzle ORM 0.45 (1.0 is still beta), @hono/node-server 2.
- 2026-09-24: Better Auth tables were generated with the Better Auth CLI (`auth generate`, username + emailOTP plugins). `user.theme` is an enum column, NOT NULL, default `'system'`. The auth config must declare it as `{ type: ['system','light','dark'], required: true, defaultValue: 'system', input: false }` and set `advanced.database.generateId` to `newId` (ULIDs).
- 2026-09-24: Author, actor, creator, uploader, resolver, claimer and deleter FKs are nullable with `ON DELETE SET NULL`, so content survives account deletion and shows a "deleted user". `team.owner_id` is `RESTRICT`, because account deletion is blocked while the user owns a team.
- 2026-09-24: The `activity` table has no foreign keys (only indexes), so the append-only audit log outlives purged entities. The per-user security log lives in `activity` rows with `team_id` NULL and `entity_type` `user` or `api_key`.
- 2026-09-24: `attachment.team_id` is nullable, only for `user_avatar` uploads, which belong to no team.
- 2026-09-24: Extra constraints beyond SPEC §4: `status` is unique per (project, name), with a partial unique index allowing one default status per project; `role` allows one `is_everyone` role per team (partial unique); `task_dependency` has a CHECK against self-blocking. Team slugs and project keys are unique only among non-deleted rows (partial unique indexes), so restoring an item whose slug or key was reused is a `conflict`.
- 2026-09-24: `search_index` (FTS5) makes `entity_type` UNINDEXED too (SPEC lists it as indexed), so the word "task" in a query doesn't match every task. Filter types with `entity_type IN (…)`. It uses the `porter unicode61 remove_diacritics 2` tokenizer with `prefix='2 3'` for as-you-type search.
- 2026-09-24: Live events carry `teamId: string | null` plus an optional `userId` (the recipient of personal events), because `me.updated` has no team. For `activity.created`, `parentType`/`parentId` name the entity the activity row is about.
- 2026-09-24: Wire timestamps are ISO 8601 strings. Attachment deletes and other deletes return `{ ok: true }`. `GET /api/subscriptions?entityType&entityId` was added to the core contract so pages can show the subscribe toggle.
- 2026-09-24: `BASE_URL` defaults to `http://localhost:5173` (the Vite dev server) in development and to `http://localhost:$PORT` otherwise. Production requires it to be set. `.env` in the working directory is loaded when present, and real environment variables take precedence.
- 2026-09-24: The server resolves the SPA build from the working directory (`dist/web`), like Hono's `serveStatic`. The server bundle keeps all npm packages external (production runs from a checkout with `node_modules`), and the build copies the SQL migrations to `dist/server/migrations`. `npm run db:migrate` runs `server/db/migrate-cli.ts` through tsx.
- 2026-09-24: MCP tools are declared with `defineTool` (`server/mcp/tools/define.ts`) and collected into one list per module. `registerTools` registers them on each per-request `McpServer`.
- 2026-09-24: The foundation implements the backup job (`server/jobs/backups.ts`: `VACUUM INTO`, keep 14, mirror uploads). Claim and purge jobs remain for the tasks and core modules.
- 2026-09-24: Role `position` ranks higher-is-higher (Discord style). `@everyone` is always 0, and the seeded Admin role is 1. Status `position` is an integer column order, ascending.
- 2026-09-24: Removed `next-themes`, which shadcn's sonner component pulls in. The Toaster uses `web/lib/theme.ts`. shadcn `use-mobile` and the sidebar skeleton were adjusted to satisfy the React Compiler lint rules (no setState in effects, no `Math.random` during render).
- 2026-09-24: `npm audit` reports 4 moderate advisories in drizzle-kit's dev-only `@esbuild-kit` dependency (esbuild dev-server CORS). They don't reach production, so they are accepted until drizzle-kit drops the dependency.
- 2026-09-24: `dev:server` runs `node --watch --import tsx` instead of `tsx watch`. Under `concurrently` on Windows, the `tsx watch` child hung before it could listen, probably because of how its IPC channel is inherited. Logs are always JSON, and `dev:server` pipes them through the `pino-pretty` CLI. An in-process pino-pretty transport was dropped, so production never loads a dev dependency.
- 2026-09-24 (core): Live events can be queued inside a transaction with `queueLiveEvent(tx, …)` (re-exported as `emitAfterCommit` from `server/services/events.ts`); `db.write` delivers them after commit and drops them on rollback. `recordActivity` uses it to emit `activity.created` for every row, so feature services get audit-log live updates for free. Account-level rows (team `null`) are delivered only to their user (`userId`), like personal events.
- 2026-09-24 (core): The MCP endpoint is stateless, so only `POST /mcp` is served; `GET` and `DELETE /mcp` answer 405 with `Allow: POST` (what the MCP spec prescribes for servers without sessions or server-initiated streams), instead of opening a stream that could never carry anything.
- 2026-09-24 (core): The 10/min/IP auth limit counts `POST /api/auth/*` only; session reads (`get-session`) and OAuth redirects are not throttled, or the web app would lock itself out. Better Auth's own per-path limits stay on (3 sign-in/sign-up attempts per 10 s, one code email per 60 s as the resend cooldown), backed by the app's token buckets (`deps.rateLimiter`) instead of Better Auth's process-global memory store. The client IP reaches Better Auth through an internal `x-baton-client-ip` header set from `CF-Connecting-IP` (`TRUST_PROXY=cloudflare`) or the socket address; a client-supplied value is always stripped.
- 2026-09-24 (core): OAuth sign-ups are stored with `emailVerified = true` (SPEC §1.1). Google and GitHub are "trusted providers" for account linking as specified, but a link whose provider email is _not_ verified is only accepted when the account owner started it while signed in (`user.validateUserInfo`), so an unverified GitHub email can't be used to take over the Baton account with that address.
- 2026-09-24 (core): Better Auth endpoints outside the SPEC are disabled: `sign-in/email-otp` (a code alone never signs anyone in or up), email change, and `delete-user` (account deletion belongs to the account module, which must block it while the user owns a team). One-time codes are stored hashed. Username input is accepted in any case and stored lowercase; sign-up without a username is refused.
- 2026-09-24 (core): Security-log actions: `user.signed_up`, `user.signed_in` (meta: method, ip, userAgent), `user.password_changed`, `user.password_reset`, `user.password_set`, `user.account_linked`, `user.account_unlinked` (meta: provider), `api_key.created`, `api_key.revoked`. They are served by the added `GET /api/me/security-log`.
- 2026-09-24 (core): Notification read state and reply subscriptions are personal preferences, not team mutations, so they write no audit rows. System cleanup writes `<type>.purged` rows for items purged from Trash; unclaimed pending uploads are purged without audit rows (they were never visible to anyone but the uploader).
- 2026-09-24 (core): Soft-deleted items keep their search-index rows (restores need no reindex); search filters deleted items, replies of deleted items and deleted projects/teams at query time, and the trash purge removes the rows.
- 2026-09-24 (core): Pending uploads are visible only to their uploader; `user_avatar` attachments (no team) are readable by any signed-in user so avatars can be shown across teams. Uploading directly to a parent needs edit rights on it (tasks also accept `UPDATE_TASKS`, projects need `MANAGE_PROJECTS`). A user can hold at most 50 active API keys, and keys can only be managed from a web session.
- 2026-09-24 (core): Contract additions (additive): `GET /api/me/security-log`, `GET /api/attachments?parentType&parentId`, and the trash schemas (`trashItemSchema`, `trashListResponseSchema`, `trashItemRefSchema`) that the admin module's routes will serve from `listTrash`/`restoreItem`.
- 2026-09-24 (core): `E2E_MAILBOX=true` (test-only env var) makes the mailer also write every email as JSON into `DATA_DIR/mailbox/` (including `kind` and `code`), so end-to-end tests can complete verification and reset flows.
